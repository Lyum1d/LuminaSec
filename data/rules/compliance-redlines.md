# 绝对不能碰的合规红线（必背）

> 适用场景：SRC / 补天**已获书面授权**的漏洞挖掘（公益 SRC）。未获得书面授权的目标一律不测。
> Agent 每轮都会在系统提示词里带上本文的精简版；本页是展开版，可用 `kb_read compliance-redlines` 查阅。
> 第四~五节是**按漏洞类型的专项作业纪律**与**报告提交自查**，动手挖具体漏洞类型前应过一遍。

## 一、六条红线（违反任意一条即停止）

1. ❌ **禁止测试企业内网、内部 OA、员工办公系统、第三方合作平台**
   只打书面授权范围内、且在 `data/scope.json` 白名单内的资产。白名单之外的域名 / IP / URL，即使是从测绘结果、JS 泄露、报错信息里看到的，也不碰。

2. ❌ **禁止暴力爆破账号、高频端口扫描、DDoS 压测**
   不做影响可用性与业务连续性的行为。端口探测限最小必要范围与并发；禁止用字典爆破登录 / 验证码接口。

3. ❌ **禁止拖库、批量下载用户隐私数据**
   证明「存在」即可，不取数据。确需取证时**只截最小必要截图**（能证明问题的单条 / 单页），不批量拉取、不落盘长期保存、不外传。

4. ❌ **禁止植入后门、修改 / 删除服务器文件、篡改订单、密码等真实业务数据**
   验证写操作只允许「先添加 → 删掉自己刚加的那个对象」，绝不改 / 删他人已有数据；禁止扣款、清库存、改订单状态、重置他人密码。

5. ❌ **禁止社工钓鱼、短信轰炸**
   不发送钓鱼邮件 / 短信、不诱导真实人员操作；不调用短信 / 邮件接口做轰炸或压测。

6. ❌ **禁止横向移动**
   拿到某台主机权限后，不得以此为跳板继续探测内网其他主机 —— 内网资产属于典型的越界范围。

## 二、核心原则与授权检查（动手前必过）

- [ ] **授权确认**：目标在补天公益 SRC 的授权范围内（政府 / 学校 / 医院等公开可访问资产），且已核对厂商声明的测试范围（授权域名 / IP / 子域）——`data/scope.json` 必须已包含该范围。
- [ ] **最小影响**：所有测试操作遵循「**证明存在即可**」，绝不扩大测试范围。
- [ ] **合规审查**：确认**未使用高并发扫描器、未跑自动化脚本**，且没有任何可能影响业务连续性的测试。

## 三、轻量测试的边界：**「扫路径」≠「遍历接口」**

> **背景**（2026-09-21 实测教训）：平台一度把「目录扫描」也归入禁止项，导致 **某授权目标首轮
> 完全没跑目录扫描**，可能漏掉普通漏洞。补天规则明确将「**敏感目录扫描**」列为许可的轻量测试方式。

| 行为 | 判定 | 说明 |
| --- | --- | --- |
| **抓包改参、简单注入验证** | ✅ 允许 | 补天明确许可 |
| **敏感目录 / 文件扫描**（`dirsearch` 一类） | ✅ **允许** | 扫的是**不存在的路径**（404/403），不触碰业务数据；**必须带速率限制、合理字典、小步进行** |
| 未授权访问验证 | ✅ 允许 | 只读 |
| **对核心业务接口批量换参数 / 换对象 ID**（遍历接口） | ❌ 禁止 | 会直接影响业务连续性，改为**少量、串行、逐点** |
| **并发请求、空参数模糊测试** | ❌ 禁止 | 同上 |
| **敏感后缀连发**（`.zip`/`.git`/`.HEAD`/`.svn`/`.bak` 一次性连续请求） | ❌ 禁止 | 实测会触发目标 IPS **直接封禁源 IP**（tgt-f.edu.cn 真实教训）；确需探测须**分散、带间隔、少量** |
| 高并发扫描器、口令爆破、DoS、拖库 | ❌ 禁止 | 见第一节红线 |

**记法**：**扫路径（允许，带限速）｜遍历接口（禁止）**。

**工具侧配套**：`dirsearch` 已补 `network_control` 声明（限速 `--max-rate`、并发 `-t`），
自动注入保守速率后即可安全使用。

- [ ] **拒绝服务**：未进行任何形式的 DoS / DDoS 或资源耗尽测试。
- [ ] **数据安全**：未进行拖库、批量下载、窃取或转移任何业务数据。
- [ ] **业务接口**：未对核心业务接口（增、删、改）进行**自动化遍历、并发请求或空参数模糊测试**。
- [ ] **数据清理**：测试完毕后，已删除测试记录及产生的测试数据，未保存或传播任何敏感信息。

## 四、通用红线行为检查（收尾时逐条回看）

- [ ] **拒绝服务**：未进行任何形式的 DoS / DDoS 或资源耗尽测试。
- [ ] **数据安全**：未进行拖库、批量下载、窃取或转移任何业务数据。
- [ ] **业务接口**：未对核心业务接口（增、删、改）进行**自动化遍历、并发请求或空参数模糊测试**。
- [ ] **数据清理**：测试完毕后，已删除测试记录及产生的测试数据，未保存或传播任何敏感信息。

## 五、按漏洞类型的专项作业纪律（重点）

### 1. 权限获取类（命令执行、文件上传、RCE）

- [ ] **立即停止**：证明可获取权限后，**立即停止**后续操作。
- [ ] **禁止读取**：避免读取 / 下载源代码、配置文件及敏感数据。
- [ ] **禁止内网**：避免利用该权限做内网横向移动、提权或植入后门 / 木马。

### 2. 文件读取漏洞（LFI / 任意文件读取）

- [ ] **证明文件**：仅使用 `/etc/passwd`、`web.xml`、`index.php` 等**通用非核心文件**证明存在性。
- [ ] **禁止打包**：避免打包下载整个应用源代码，避免读取敏感数据文件。

### 3. SQL 注入

- [ ] **风险证明**：仅通过报错信息、延时注入等方式证明数据读取风险。
- [ ] **禁止写入**：避免使用 `into outfile` / `into dumpfile` 等语句写文件。
- [ ] **禁止拖库**：避免批量获取业务敏感表数据。

### 4. SSRF

- [ ] **请求构造**：验证请求**确实可构造**（如取到内网服务器 Banner），而非仅依赖 DNSLog。
- [ ] **禁止扫描**：避免对内网做**大范围端口扫描**，避免把目标当跳板攻击其他主机。

### 5. 越权（IDOR / 水平与垂直越权）

- [ ] **交叉验证**：严格使用**自己可控的两个测试账号**进行交叉验证。
- [ ] **规避操作**：尽量规避增 / 删 / 改操作；若无法避免，在**最小影响**下操作并**立即恢复**。
- [ ] **禁止遍历**：避免无差别、大范围地遍历所有接口和用户 ID。

### 6. XSS

- [ ] **截图证明**：仅提供 Payload 及弹窗（或 JS 执行上下文）的截图。
- [ ] **禁止恶意**：避免使用 XSS 平台进行 Cookie 劫持、挂马、钓鱼。
- [ ] **数据清理**：测试后删除插入的测试数据；若无法删除，在报告中**备注插入点**。

## 六、报告与提交自查

- [ ] **信息脱敏**：提交的报告中，对敏感数据（凭据 / Token / 个人数据 / 内部地址）做脱敏处理。
- [ ] **合规描述**：清晰描述漏洞复现步骤，且**不包含任何违规操作的截图或数据**。
- [ ] **口径如实**：只写有工具输出支撑的结论；证否项与候选项如实分列，不抬高危害等级。

## 七、快要越线时该怎么做

- **改保守做法**：优先用只读、单点、最小化的方式取证（GET / 差分对比 / 单次请求），而不是「工具能做到就做」。
- **停下来问**：若某个方向必须触碰红线才能继续，停止该方向，向用户说明「为什么需要」与「替代方案」，由用户决定。
- **能力不等于授权**：工具有利用能力，不代表允许对你当前的目标使用。

## 八、项目里已实现的机械闸门（红线之外的第二道防线）

- `data/scope.json` 授权白名单：命令行工具 / HTTP 重放器 / py_exec 执行前强制校验，白名单为空一律拒绝执行；**绕过 scope 本身即违规**。
- HTTP 重放器只允许只读方法（GET / HEAD / OPTIONS），写入方法硬禁用；py_exec 受控通道同样只放行只读方法。
- 风险分级闸门：L2 漏洞验证需用户确认，L3 权限 / 横向 / 接管需二次确认（含 `py_exec` 代码执行）。
- 统一流量调度：同主机 / 同根域名并发各 1（**天然禁止并发请求**）、滑动窗口预算与突发限制（抑制自动化遍历）、目标级暂停与熔断（触发即停）。
- **测试数据用完即清**：技术分析产生的落盘文件（响应正文副本）保留期默认 1 天（`AGENT_PY_EXEC_PERSIST_KEEP_DAYS`），服务启动时自动清理过期分桶，并提供手动清理接口。
- 全程留痕：每步命令与输出留档，报告只写证据确凿的结论。
